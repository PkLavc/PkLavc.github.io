Amazon Transcribe Turbo Enhances Voice Agents with Semantic Turn-Taking and Runtime ASR Hints

AWS announces the public preview of Amazon Transcribe Turbo, a next-generation speech-to-text model with enhanced accuracy and new features like semantic turn-taking and runtime ASR hints for more natural and effective voice agents.

Published November 27, 20265 min readAI and models

Confirmed facts

Amazon Transcribe Turbo, a next-generation speech-to-text model, is now available in public preview in US East (Ohio) for both batch and streaming operations. The English batch processing capability for Transcribe Turbo is generally available in most AWS Regions.

This new model offers improved accuracy, supports custom vocabulary, and automatically formats numbers, dates, currency, phone numbers, and addresses according to locale conventions.

For streaming, Transcribe Turbo supports English, Portuguese, French, Italian, German, and Spanish. In English streaming, the Word Error Rate (WER) is approximately 14% relatively lower compared to the current production model. For the other supported streaming languages, the WER drops by 11% relatively. Streaming formatting accuracy also improves by more than 20 points.

For batch processing, Portuguese, French, Italian, German, Spanish, Chinese, Japanese, Korean, and Arabic are now in preview, demonstrating approximately 16% lower WER.

Adopting the base Transcribe Turbo model requires no API, code, or SDK changes.

Two new features are introduced for streaming voice agents: Semantic turn-taking and Runtime ASR hints. These features are available for English at launch and will extend to other languages by the end of December 2026.

Semantic turn-taking detects when a caller has finished speaking by analyzing both the content of their speech and their prosody, moving beyond reliance on silence alone. This aims to prevent mid-sentence interruptions and avoids unnecessary delays for short answers. It responds in approximately 615 ms with a 5% interruption rate and is tunable. Developers can enable this feature by turning on `EndOfTurnDetection`.

Runtime ASR hints allow client applications to provide contextual information, such as menu options, expected names, and specific entity types (e.g., date, phone number, currency), before each turn. This differs from static custom vocabulary, which is set once per session. On English customer service data, the use of hints increased menu-routing accuracy from 87% to 97%. Developers can utilize this feature by sending hints within a `ConfigureEvent`.

Both Semantic turn-taking and Runtime ASR hints are provided at no additional charge.

Technical analysis

The introduction of Amazon Transcribe Turbo signifies a notable advancement in automated speech recognition (ASR) technology, addressing both fundamental accuracy and sophisticated conversational dynamics. The designation as a "next-generation" model is substantiated by specific, measurable improvements and the integration of new features designed for real-time interaction.

**Core Accuracy Enhancements and Developer Adoption**

The confirmed relative Word Error Rate (WER) reductions—approximately 14% for English streaming, 11% for other supported streaming languages, and 16% for batch preview languages—represent a substantial improvement in ASR reliability. For software engineers, lower WER directly translates to more accurate transcripts, which can reduce the need for post-processing, manual corrections, or complex error handling in downstream natural language understanding (NLU) systems. The reported improvement of over 20 points in streaming formatting accuracy further enhances the utility of transcripts, particularly for applications that parse structured data like dates, currency, or addresses, by providing cleaner, more consistent output.

A key engineering consideration is the stated compatibility: the base Transcribe Turbo model requires no API, code, or SDK changes. This design choice facilitates a low-friction adoption path for existing Amazon Transcribe users. Developers can integrate the core accuracy improvements as a drop-in replacement, minimizing migration effort and accelerating the time-to-value for applications that rely on speech-to-text transcription.

**Semantic Turn-taking: Advancing Conversational Flow**

Traditional voice activity detection (VAD) systems often rely on simple silence thresholds to determine when a speaker has finished. This approach frequently leads to suboptimal user experiences, such as prematurely cutting off speakers or introducing awkward pauses after short responses. Semantic turn-taking directly addresses these limitations by incorporating a more sophisticated understanding of speech. By analyzing both the linguistic content ("what they said") and prosody (the rhythm, stress, and intonation of speech), the system can infer conversational intent more accurately.

For developers building voice agents, this feature enables more natural and human-like interactions. The confirmed response time of approximately 615 ms with a 5% interruption rate provides concrete performance metrics, allowing engineers to design conversational flows with predictable latency and user experience. The tunability of this feature offers flexibility, enabling developers to optimize the balance between responsiveness and interruption sensitivity to suit specific application requirements, such as high-stakes customer service interactions versus casual voice commands. This capability can significantly improve user satisfaction and task completion rates by reducing frustration caused by misinterpretations of turn boundaries.

**Runtime ASR Hints: Dynamic Context for Enhanced Recognition**

While custom vocabularies have been a standard method for improving the recognition of domain-specific terms, they are typically static for the duration of a session. Runtime ASR hints introduce a dynamic, turn-by-turn contextualization mechanism. This allows client applications to provide highly specific information—such as expected menu options, names, or entity types (e.g., date, phone number, currency)—immediately before each utterance. This capability represents a significant shift in how developers can influence the ASR process.

From an engineering perspective, sending hints in a `ConfigureEvent` before each turn allows the client application to dynamically guide the ASR model, reducing ambiguity in real-time. The confirmed improvement in menu-routing accuracy from 87% to 97% on English customer service data demonstrates a substantial practical benefit. This is particularly impactful in structured conversational scenarios, such as interactive voice response (IVR) systems, automated customer support, or data entry applications where specific inputs are anticipated. By providing precise context, developers can build more robust and accurate voice interfaces, leading to fewer recognition errors and a more efficient user experience.

**Overall Developer Impact**

The combination of enhanced core accuracy and these two new, no-additional-charge features provides a compelling set of tools for developers working on conversational AI. The focus on streaming and voice agents indicates a strategic emphasis on real-time, interactive human-computer interfaces. Engineers can leverage these advancements to create more reliable, natural, and efficient voice-enabled applications, potentially expanding the scope and effectiveness of automated services across various industries. The explicit enablement requirements (`EndOfTurnDetection` and sending hints in a `ConfigureEvent`) mean developers retain control over when and how these advanced features are integrated into their applications.
