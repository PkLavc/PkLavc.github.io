AWS EC2 M9gd instances with Graviton5 processors and Nitro Isolation Engine now available, supporting agentic AI and mathematically proven cloud security

AWS launches M9gd EC2 instances featuring Graviton5 processors and the groundbreaking Nitro Isolation Engine, offering enhanced performance for agentic AI workloads and a new level of mathematically proven cloud security.

Published November 26, 20264 min readcloud platforms

Confirmed facts

As of November 25, 2026, Amazon EC2 M9gd instances are available in the Asia Pacific (Seoul) region. These instances are powered by AWS Graviton5 processors, which represent the fifth generation of custom-designed CPUs from AWS.

Graviton5 processors deliver up to 25% better compute performance compared to AWS Graviton4-based M8gd instances. Specific performance improvements include being up to 30% faster for databases, up to 35% faster for web applications, and up to 35% faster for machine learning workloads.

M9gd instances are built on the sixth-generation AWS Nitro System and are the first to incorporate the Nitro Isolation Engine. This engine utilizes formal verification to provide mathematical assurance that customer workloads are isolated from each other and from AWS operators. This approach is stated to pioneer a new standard for mathematically proven cloud security.

These instances are designed for a broad spectrum of general-purpose workloads, including application servers, microservices, gaming, caching, and containers. They also provide the performance required for agentic AI use cases, such as real-time reasoning, code generation, and multi-step orchestration.

M9gd instances include local NVMe-based SSD block-level storage. This storage is intended for workloads that require high-speed, low-latency local access for purposes like scratch space, temporary files, and caches.

Customers can purchase M9gd instances in the Asia Pacific (Seoul) region through various options, including Savings Plans, On-Demand, Spot Instances, Dedicated Instances, or Dedicated Hosts.

Technical analysis

The introduction of Amazon EC2 M9gd instances marks a notable evolution in AWS's compute offerings, integrating the Graviton5 processor and the Nitro Isolation Engine. This combination addresses both performance demands across a range of workloads and foundational security concerns within multi-tenant cloud environments. For software engineers, these advancements translate into direct implications for application design, deployment strategies, and security postures.

The Graviton5 processors' stated performance improvements, with up to 25% better compute performance overall compared to Graviton4, provide a clear path for optimizing cost-performance ratios. The specific gains—up to 30% faster for databases, 35% faster for web applications, and 35% faster for machine learning—indicate targeted architectural enhancements within the Graviton5 design. For database administrators and developers, this could mean higher transaction throughput or reduced query latency without requiring a scale-out architecture. Web application developers may observe improved response times and increased concurrent user capacity. In machine learning contexts, particularly for inference or data preprocessing stages that are CPU-bound, the 35% speedup can directly reduce processing times and operational costs. These improvements are significant for workloads that benefit from a balanced CPU, memory, and network profile, which is characteristic of the M-series instance family.

The Nitro Isolation Engine represents a significant shift in cloud security guarantees. By employing formal verification, AWS aims to provide mathematical assurance of workload isolation. Traditional security measures often rely on extensive testing, auditing, and penetration testing, which can identify vulnerabilities but do not mathematically prove the absence of certain classes of flaws. Formal verification, applied at the hypervisor level within the Nitro System, offers a higher degree of confidence that customer workloads are genuinely isolated from each other and from AWS operators. This has profound implications for highly regulated industries, such as finance, healthcare, or government, where stringent compliance requirements demand verifiable isolation. Engineers deploying sensitive applications can leverage this assurance to meet compliance objectives and enhance trust in the underlying infrastructure, potentially simplifying security audits and risk assessments. The reduction of the attack surface through formally verified isolation mechanisms at the hypervisor level is a direct engineering consequence, as it minimizes avenues for unauthorized access or interference.

The explicit mention of M9gd instances supporting "agentic AI use cases" like real-time reasoning, code generation, and multi-step orchestration is noteworthy. Agentic AI workloads often involve iterative processing, decision-making, and interaction with various data sources or APIs. These tasks can be computationally intensive, requiring efficient CPU performance and low-latency access to data. The Graviton5's performance uplift, particularly for machine learning, directly contributes to the efficiency of these AI agents. Furthermore, the enhanced security provided by the Nitro Isolation Engine is critical for agentic AI, as these systems may handle sensitive data, execute complex logic, or interact with critical business systems. Ensuring that an AI agent's execution environment is mathematically isolated from other tenants or potential insider threats can mitigate risks associated with data leakage, unauthorized access, or manipulation of agent behavior. The local NVMe SSD storage further supports these use cases by providing high-speed scratch space for temporary files, intermediate reasoning steps, or caching frequently accessed models or data, which can be crucial for maintaining real-time performance in agentic workflows.

The inclusion of local NVMe-based SSD block-level storage offers practical benefits for a variety of applications. For databases, this can accelerate operations involving temporary tables, transaction logs, or frequently accessed indexes. Web applications can leverage this for session data, caching, or temporary file storage, improving responsiveness. For general-purpose computing, the high-speed, low-latency local storage can significantly enhance the performance of applications that generate or process large amounts of temporary data, reducing reliance on network-attached storage for transient operations. This design choice allows developers to optimize I/O-intensive components of their applications by placing temporary data on the fastest available storage, directly impacting application throughput and latency.
