Rapidly scaling online storage to serve over 1 billion ChatGPT users (Part II)

OpenAI shares technical details on how they scaled their Habitat online storage system with multi-tenancy, global caching, and Azure Cosmos DB to deliver 12x faster reads for over 1 billion ChatGPT users.

Published October 23, 20263 min readCloud Platforms
Image source: Google

Confirmed facts

OpenAI has detailed how it scaled its Habitat online storage system to serve over 1 billion ChatGPT users. This scaling effort resulted in a 12x improvement in read speeds for ChatGPT.

The architecture implemented for Habitat includes reliable multi-tenancy and global caching layers. It also leverages Azure Cosmos DB as a foundational component. A key aspect of the design involves isolating workloads across shared infrastructure to maintain reliability.

Advanced caching strategies were deployed, which significantly reduced the load on the underlying database by 85%. Furthermore, the system utilizes Azure Cosmos DB's capabilities for global distribution and automatic indexing to support its operational requirements. These architectural changes led to a 40% reduction in infrastructure costs and improved median response times.

Technical analysis

Scaling an online storage system to support over a billion users, particularly for an interactive AI application like ChatGPT, presents significant engineering challenges. The core requirements typically include extremely low latency, high throughput, global availability, and cost efficiency. OpenAI's approach with Habitat demonstrates a practical application of distributed systems principles to meet these demands.

The implementation of reliable multi-tenancy is critical for managing a large user base efficiently. In a multi-tenant environment, multiple users or organizations share the same underlying infrastructure. The confirmed fact of "isolating workloads across shared infrastructure" directly addresses common multi-tenancy issues such as the "noisy neighbor" problem, where one tenant's heavy usage can degrade performance for others. This isolation is essential for maintaining consistent performance and reliability across a diverse and massive user base, preventing resource contention and ensuring data integrity and security within a shared environment.

The deployment of "global caching layers" is a standard, yet complex, strategy for improving read performance and reducing database load in globally distributed applications. The reported "85% reduction in database load" is a substantial achievement, indicating a highly effective caching strategy. This level of load reduction implies that the vast majority of read requests are served directly from the cache, bypassing the database. For a global user base, a global caching layer minimizes network latency by serving data from a geographically proximate cache, directly contributing to the "12x faster reads" experienced by ChatGPT users. Such a reduction in database operations also directly translates to lower operational costs, as database read operations are often a primary cost driver in large-scale applications.

Leveraging Azure Cosmos DB for its "global distribution and automatic indexing" capabilities is a strategic choice for a system requiring high availability and low-latency access worldwide. Cosmos DB is a managed, globally distributed, multi-model database service designed for high-performance applications. Its global distribution allows data to be replicated across multiple Azure regions, enabling users to access data from the closest region, which inherently reduces latency. Automatic indexing simplifies data management and query optimization, ensuring that queries remain performant even as data volumes grow and schema evolves, without requiring manual index tuning by developers. This offloads significant operational burden from OpenAI's engineering teams, allowing them to focus on application-level logic rather than database administration.

The combined effect of these architectural decisions – multi-tenancy with workload isolation, aggressive global caching, and a globally distributed managed database – has tangible engineering consequences. The "12x faster reads" directly translates to a more responsive and fluid user experience for ChatGPT users, which is paramount for an interactive AI service. The "40% reduction in infrastructure costs" highlights the economic benefits of optimizing storage and data access patterns at scale. This cost efficiency allows OpenAI to sustain its massive user base more affordably, potentially enabling further investment in AI model development or service expansion. The "improved median response times" further reinforces the positive impact on user experience and overall system performance.

While the article confirms the architectural components and their benefits, specific implementation details were not disclosed. For instance, the exact technologies used for the global caching layers (e.g., Redis, Memcached, or a custom solution), the specific mechanisms for workload isolation within the multi-tenant architecture (e.g., containerization, virtual machines, or logical partitioning), or the detailed schema design within Azure Cosmos DB were not provided. Similarly, the specific consistency models employed for Cosmos DB, which can impact performance and data integrity trade-offs, were not detailed. These specifics would offer deeper insights into the engineering choices made.
