Google lanza A2UI 1.0: Un Protocolo Abierto para la UI Generativa y Experiencias Agentes

Google introduce A2UI 1.0, un protocolo abierto diseñado para facilitar la creación de interfaces de usuario generativas para agentes de IA. Este nuevo marco ofrece SDKs para diversas plataformas e idiomas, lo que permite a los desarrolladores construir experiencias dinámicas e interactivas de agente con facilidad.

Datos confirmados

Google anunció A2UI 1.0 en 2026-11-11. El resumen confirmado lo describe como un protocolo abierto para interfaces de usuario generativas y experiencias agentes.

El protocolo se describe como permitiendo que los agentes de IA rendericen pantallas interactivas, nativas a través de aplicaciones web, móviles y de escritorio.

La información de liberación lista SDKs de código abierto para React, Angular, Flutter y SwiftUI, y SDKs agente para Python, TypeScript y Dart.

Las características clave confirmadas incluyen llamadas de función bidireccional, formatos de inferencia swappable y unión de datos segura.

  • A2UI 1.0 fue anunciado como un protocolo abierto para la IU generativa.
  • El protocolo se describió como agentes de IA que permiten realizar pantallas nativas interactivas.
  • Se anunció el apoyo de Renderer y agente SDK.
  • Se anunciaron llamadas de función bidireccional, formatos de inferencia swappable y unión segura de datos.

Análisis técnico

El análisis técnico comienza con el alcance divulgado. El anuncio confirmado describe un protocolo, SDKs de renderista, SDKs de agente y características de interacción. El propósito revelado es permitir que los agentes hagan pantallas nativas interactivas. La lista SDK de renderizado divulgada y la lista de agente SDK establecen una superficie de integración de marco cruzado para equipos de ingeniería.

Se describe la función bidireccional llamada característica, pero la evidencia aprobada no proporciona requisitos de implementación o semántica de tiempo de ejecución. Se describen los formatos de inferencia intercambiables y la unión segura de datos. La fuente aprobada no reveló mediciones de desempeño, modelos de amenazas de seguridad o arquitectura de despliegue.

La evidencia apoya una inferencia sobre el trabajo de integración: los equipos que evalúan interfaces de agente tendrían que mapear acciones de agente a las API de componentes marco. Esa inferencia está vinculada al alcance de SDK revelado y no es una capacidad de producto confirmada.

  • El alcance de SDK revelado es una superficie de integración para agente y código UI.
  • La función de interacción confirmada plantea preguntas de ingeniería sobre el manejo de función-call.
  • La fuente aprobada no reveló detalles de ejecución, capacitación, desempeño ni despliegue.
